# Overlay 可读性、呈现与多屏修复

依据：用户提供的编辑态、悬停、关闭编辑器后三张截图，以及逐个出现和跨屏误隐藏的复现描述。

## 定位结果

- 默认 WPF Button 模板在 hover 时覆盖为浅蓝底，与白色对勾缺少对比；未完成任务却一直画 ✓，状态表达也不准确。
- 日常模式主动把面板背景改成透明，文字依靠阴影无法在浅色窗口上稳定辨认。
- 每个任务创建独立 CompletionWindow；切换时 Close 全部再逐个创建/Show/Align，引入窗口创建、首帧渲染和位置调整开销。
- 系统全屏状态在比较显示器前直接触发全局隐藏，与用户要求的同屏策略不符。

## 修复设计

1. 同一视觉窗口统一绘制深色半透明底、文字与所有勾选框；编辑/日常采用相同主体样式。未完成默认空框，hover 显示浅薄荷底与深绿对勾，pressed 加深，不使用系统浅蓝按钮模板和文字发光阴影。
2. 增加一个长期复用的非激活输入窗口，内容只有近乎透明的命中区域，通过 Win32 region 仅覆盖可见勾选框；其余区域仍穿透到其他进程。hover/pressed 状态转发到视觉窗口的同一控件，不另画第二套勾选框。
3. 窗口数量固定为一个视觉窗口和一个输入窗口；隐藏/恢复保留窗口与任务控件。只有任务或布局变化时更新，不按任务逐个创建顶层窗口。
4. 日常面板按未完成行数收拢高度，最大为当前显示器工作区；溢出时预留提示行。编辑高度保留用户设置，可调整与滚动；滚动条改为细暗色样式。
5. 全屏应用与 Overlay 按最大相交面积归属显示器，仅同屏全屏隐藏。独占和演示信号也必须同屏；锁屏仍全局隐藏。后台全屏不单独检测。

## 验证与交付

- 纯逻辑测试：同屏/跨屏全屏、普通最大化、无效窗口、负坐标、锁屏、布局容量与溢出预留。
- Windows 离屏验证：正常/hover/pressed 样张、日常底色、统一勾选视觉、输入 mask 只含框区、反复刷新复用控件且窗口数不随任务数增长。
- 不在共享桌面启动可见测试窗口、移动鼠标、抢焦点或自动切换全屏。实际跨进程命中及混合 DPI 在隔离环境验收。
