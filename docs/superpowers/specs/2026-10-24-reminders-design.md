# Reminders：Windows 任务 Overlay 设计

状态：用户于 2026-10-24 确认并授权开始实现，随后明确选择 Tauri + React 编辑器并接受架构调整。日常模式仅勾选框响应点击、其他区域穿透。

## 目标与边界

提供一个离线、简洁的 Windows 桌面任务工具，支持重复任务和带截止日期的一次性任务。编辑器管理任务与历史，Overlay 只显示当前可执行且未完成的任务。完成后立即隐藏；全部完成时隐藏整个 Overlay，并在有新周期或新任务时自动恢复。

首版面向 Windows 10/11 x64，中文界面，不依赖服务器、账号或联网。不包含云同步、游戏接口、自动领取、弹窗提醒和任意 Cron 表达式。

## 技术方案比较

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| C# / .NET 10 / WPF | Windows 原生窗口集成直接；数据绑定与测试工具成熟 | 默认编辑器控件外观不符合用户期望，需要额外视觉工作 |
| Tauri / Rust / React（用户选择） | 界面布局与视觉设计自由，可使用现代 Web 组件和无界面浏览器验收 | 增加 WebView 与进程通信，需要明确窗口生命周期与进程故障处理 |
| Electron | UI 开发便利 | 对常驻、极简的小工具而言运行时体积与资源成本偏高 |

采用 Tauri 2 + React + TypeScript 编辑器，复用已验证的 .NET 10 Core/Persistence 与 WPF + Win32 Overlay。后台进程提供统一任务服务、原生 Overlay 和托盘；Tauri 通过标准输入输出 JSONL 协议访问它，不另建任务引擎，不启动 HTTP 服务。托盘复用 .NET NotifyIcon。原 WPF 编辑器移除，避免出现两套编辑器。

编辑器采用暖白主内容、深绿侧栏和青绿强调色，任务卡片承载名称、日程、状态与完成操作；历史和显示设置使用独立页面。表单在弹层内编辑。Overlay 保持极简，视觉不追随编辑器复杂布局。

Tauri 启动后台子进程，并隐藏/显示编辑器时通知后台进入日常/编辑模式。托盘打开请求由后台发送事件给 Tauri。前端意外退出会关闭后台 stdin，后台按 EOF 退出并释放窗口和数据锁；正常退出按相同流程清理。进程通信失败必须在编辑器可见地报告，不能把未保存操作显示为成功。

## 编辑器与日常模式

- 首次启动打开编辑器；以后启动恢复任务、Overlay 几何信息和设置。
- 编辑器包含任务列表、任务编辑区、历史记录和 Overlay 设置。支持新增、修改、排序、停用与归档任务。
- 编辑器能查看本周期全部任务，包括已经完成的任务，并撤销本周期完成状态。
- 编辑器显示时，Overlay 允许拖动、缩放、点击；显示轻微背景与调整提示。编辑器可调整字体大小、透明度和置顶开关，置顶默认开启。
- 最小化或关闭编辑器都隐藏到托盘，切换日常模式。托盘提供打开编辑器、Overlay 显示开关和明确的退出入口。
- 日常模式只显示勾选框与任务名称，不显示工具栏或调整边框。仅勾选框接收点击；文字、背景与空白区域都穿透到其他进程的底层窗口。勾选不抢占键盘焦点，不激活编辑器。
- 日常模式点击勾选框只允许完成，完成行立即消失；撤销必须进入编辑器。底层应用不得同时收到勾选框上的这次点击。
- 全部完成时隐藏真实 Overlay 窗口，不以透明但仍拦截输入的窗口代替。编辑器模式仍能显示调整占位框。
- 任务超出指定高度时不静默截断：编辑模式可滚动与调整尺寸；日常模式自动扩展至屏幕可用高度，超出的未完成数量用末行提示，完整操作通过编辑器完成。

## 重复周期语义

所有日程跟随操作系统当前时区与本地时间；不提供独立时区设置。

| 类型 | 配置 | 周期边界 |
| --- | --- | --- |
| 每日 | 本地重置时间 HH:mm | 每个本地日的指定时间 |
| 每周 | 星期与本地重置时间 | 每周指定星期的指定时间 |
| 每 N 天 | 起始日期、N（正整数）、本地重置时间 | 从起始日期起，每 N 个本地日的指定时间 |
| 一次性 | 截止日期，可选具体时间 | 没有重置边界；完成后永久隐藏，除非在编辑器撤销 |

- 周期为左闭右开区间 `[开始, 下次开始)`，边界时刻属于新周期。
- 每个任务独立计算周期，不存在全局“每日清零”。
- 每 N 天采用固定日历周期，不是完成后延迟 N×24 小时。完成时间不改变后续边界。若用户期望按完成时间滚动，需要在实现前调整此项。
- 起始日期在未来的任务，在首个周期开始前不出现在日常 Overlay。
- 未完成任务过期后进入下一周期，不叠加多条欠账。
- 关闭应用、休眠或错过多个周期后，按当前系统时间直接计算正确周期，不依赖后台计数器逐个重置。
- 运行时跨周期自动刷新；系统修改时间、时区与从休眠恢复时立即重新计算，并以低频定时刷新作为兜底。
- 夏令时跳过的本地时间顺延到第一个有效时间；重复出现的本地时间固定采用较早的 UTC 时刻，避免同一周期重置两次。
- 当前完成身份由任务 ID、日程版本和本地周期起始日期确定，避免时区偏移数变化导致同一本地周期重复完成。跨时区后若本地周期日期不同，则显示新周期。

### 一次性任务

- 新建后即显示，没有周期重置，也不会因日期变化重新出现。
- 必填截止日期，可选 HH:mm。只选择日期表示该本地日结束，内部以次日 00:00 作为排他的截止边界；选择具体时间则以该时刻为截止边界。
- 未完成且当前时间已到截止边界时标记“已逾期”，仍保持显示，直到完成、停用或归档。不因到期自动完成、删除或隐藏。
- Overlay 在名称旁用简短日期或逾期标识表达状态，保持极简；编辑器显示完整截止时间。
- 截止时间跟随操作系统当前时区的本地墙上时间；夏令时的歧义处理复用重复日程规则。
- 完成状态采用稳定的一次性任务身份；修改名称、截止日期与具体时间不撤销已完成状态。类型由重复切换为一次性或反向切换时才创建新的日程版本。
- 完成与撤销记录复用统一历史事件，保留操作时的截止时间快照。

### 用户场景

1. Epic 免费游戏：每周四 00:00 重置。仅按用户指定时间提醒，不自动推断商店实际赠送时间。
2. 游戏 A 日常：每日 05:00；04:59 属于前一周期，05:00 开始新周期。
3. 游戏 B 日常：每日 04:00，与游戏 A 独立计算。
4. 检查体力：每 2 天一次；起始日期与重置时间可编辑。
5. 一次性任务：例如月底前提交资料，设置截止日期，完成后不再出现，逾期则持续显示提醒。

编辑器提供重复日程快捷创建入口和一次性任务类型，首次启动不擅自创建已启用的真实任务。

## 全屏隐藏与窗口行为

- 全屏自动隐藏的优先级高于置顶和手动显示。恢复窗口模式后自动恢复尚未完成的任务。
- 采用系统通知状态检测独占全屏/演示状态，并结合前台窗口边界与显示器边界识别无边框全屏、浏览器 F11 与视频全屏。
- 排除桌面、任务栏、自身窗口和无效窗口；普通最大化窗口保留任务栏，不应被误判为全屏。
- 首版采用保守的全局策略：任一显示器上的前台应用进入全屏，整个 Overlay 隐藏。后台且没有获得前台的全屏窗口不会单独触发。
- 全屏开始/结束以约 500 毫秒轮询识别；隐藏后不持续置顶，不改变其他程序的窗口层级。
- 置顶关闭时，Overlay 按普通窗口层级显示。日常模式不出现在任务栏或 Alt+Tab 中。
- 支持多显示器、负屏幕坐标与每显示器 DPI；断开显示器后将 Overlay 调整回可见工作区。
- 穿透机制必须在跨进程窗口上验收，不能仅用 WPF 的 IsHitTestVisible 作为实现。显示文字使用穿透窗口，勾选框使用独立的非激活交互区域；具体 HWND 组织在实现计划中固定。

## 数据与历史

- 默认存储于 `%LOCALAPPDATA%\Reminders`，包含版本化 JSON、备份和必要的错误日志。
- 数据分为任务定义、日程版本、完成/撤销事件、Overlay 设置。事件保留任务名称、当时周期范围、系统时区与 UTC 操作时间快照，重命名或修改日程不会改写历史。
- 历史页面按时间倒序查看完成与撤销记录，支持任务过滤。首版不把未完成周期伪装成完成记录，也不提供历史补签。
- 修改重复规则或切换任务类型创建新日程版本，旧记录保留；当前周期按新规则重新开始，保存前在编辑器说明。仅修改名称、显示顺序或一次性任务的截止时间不重置完成状态。
- 停用任务不显示；重新启用时沿用原日程与当前周期状态。归档任务从活动列表移除，历史仍保留。
- 完成与撤销先成功持久化，再更新 Overlay；保存失败时保持原状态并提供可见错误，避免误报完成。
- 同目录临时文件写入后原子替换，保留上一次有效备份。读取失败不自动用空数据覆盖；备份恢复需明确提示。
- 数据目录持有 `.instance.lock` 独占文件句柄，防止不同路径别名绕过单实例保护；第二个后台拒绝启动，编辑器显示失败信息，不读取旧状态进行写入。

## 模块职责

- Core：任务模型、周期计算、完成状态、历史事件及输入校验；使用可注入时间源。
- Persistence：版本化数据序列化、原子写入、备份和恢复策略。
- Windows 后台：复用 Core/Persistence；全屏检测、窗口样式、非激活交互、DPI/显示器、系统时间事件、托盘与 JSONL 协议。
- Tauri 平台层：后台子进程生命周期、请求关联、窗口显示/隐藏与托盘事件桥接。
- React Editor：任务与历史界面、输入校验、错误提示、Overlay 设置；只渲染后台当前周期投影，不独立计算周期。
- Overlay：编辑/日常模式呈现、任务完成入口与几何信息；复用 Core 状态，不另建完成状态或计时逻辑。

## 验证与交付

开发约束补充（2026-10-24）：共享桌面禁止真实输入、焦点和可见全屏自动化。日常采用核心测试、构建和不显示窗口的离屏渲染；真实输入验收必须在隔离的 Windows Sandbox/虚拟机中执行。

1. 核心自动化测试：每日 04:00/05:00 前后、周四重置、每两天跨月/跨年、未来起始日期、睡眠后跨周期、时区及夏令时边界、完成/撤销与日程变更；一次性任务的日期截止、指定时间截止、逾期仍可见、完成后跨日不复现与编辑截止时间保留完成状态。
2. 存储测试：重启恢复、中文内容、损坏数据、备份与写入失败；失败不能更改内存完成状态。
3. Windows 编译检查；提供构建/运行/发布命令及 Windows x64 自包含发布方式。
4. Windows 实机清单：编辑器/托盘切换，跨进程点击穿透和不抢焦点，末项完成隐藏/下周期恢复，独占与无边框全屏，视频全屏、普通最大化、多屏及 DPI。
5. 当前开发环境为 Linux，可运行核心测试并尝试 Windows 目标交叉构建。无法在此环境执行的 Windows GUI 行为必须标为待实机验收，不能以编译通过替代。
